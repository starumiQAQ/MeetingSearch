# Service settings write `.env` without auth

Deployers configure 高德 credentials (`AMAP_KEY`, `AMAP_JS_KEY`, `AMAP_SECURITY_JS_CODE`) and `AMAP_QPS` through an in-app **Service settings** UI instead of hand-editing `.env`. Values persist by updating the local `.env` in place; the server hot-swaps the MapProvider / QPS immediately, while JS map keys still require a page refresh. Secrets are masked on read (empty field = leave unchanged; explicit clear restores today’s empty-key semantics: demo MapProvider / JS key fallback). No auth — this remains a local tool (ADR-0002); document that the process must not be exposed publicly. Rejected: browser-only storage (would leak the Web 服务 key), a second config file that overrides `.env` (two sources of truth), and a settings token for v1 (replaces one secret-management chore with another). Search preferences (Brand, Proximity objective, radius) stay out of Service settings.
